3. Remaining useful life on NASA C-MAPSS

Problem. Predict how many cycles a turbofan engine has left, on all four C-MAPSS subsets (simulated engine data, not field data).

Approach. Gradient boosting on window features vs a 2-layer LSTM vs a small Transformer; RUL target capped at 125 cycles; per-operating-condition normalisation (FD002/FD004); validation split by engine; 3 seeds per deep model; last window per test engine (official protocol).

1. Self-auditing multi-hop retrieval with calibrated abstention

Problem. Can a retrieval system know when it is failing? A synthetic corpus (1,846 documents, 2,400 two- and three-hop questions) has twin entities, relocated companies with conflicting dated facts, and typo or missing-initial name mentions.

Approach. Three retrieval paths (own BM25, an LSA dense index, an exact entity index), reciprocal rank fusion, cross-path agreement as confidence, and a logistic calibrator fit on 800 questions and evaluated on the other 1,600. The reader is rule-based and extractive, not an LLM.

Calibration and abstention (fused, 1,600 test questions)

  • Area under the risk-coverage curve: 0.0405 raw agreement to 0.0208 calibrated (0.041 to 0.049 raw vs 0.017 to 0.021 calibrated over three world seeds).
  • ECE 0.038 to 0.028. Abstaining on 17.9% of questions raised accuracy on answered questions from 88.6% to 93.8%, avoiding 101 wrong answers at the cost of 186 correct ones.
Honest caveats. Fusion did not beat BM25 in any of the three seeds (fused 0.893 / 0.903 / 0.900 vs BM25 0.897 / 0.910 / 0.915), because the weak dense path adds noise. Abstention caught only 38% of twin-ambiguous questions. These numbers say nothing about LLM quality or real corpora (a HotpotQA notebook exists but has not been run).

4. PII detector and synthetic-data quality filters

Problem. Detect and redact personal data reliably, and filter synthetic training data for defects.

Approach. Regex candidates, checksum validators (Luhn, Verhoeff for Aadhaar, SSN rules, IP octet ranges), same-clause context rules and overlap resolution; ablation on held-out templates. A second pipeline generates verifiable tasks, injects known defects and measures the filter stack.

Quality filter (3,000 generated examples, 40% injected defects): every injected defect type was caught (recall 1.0) with zero false rejections of clean items.

Honest caveats. All data is synthetic and the generator and detector share an author, so near-perfect structured-ID scores prove the method, not real-world accuracy. Name (PERSON) recall is only 0.653; production needs an NER model. The test set was reused twice during development and replaced each time with a fresh seed; earlier, lower scores are kept in results/. Injected defects are crisp, so the filter recall is an upper bound.

Live demo: pii-redaction-api.vercel.app (health: /health, POST /redact). Please do not paste real personal data.

2. Time-split fraud scoring (IEEE-CIS)

Problem. Score card transactions for fraud without leaking future information, and choose a decision threshold by business cost.

Approach. Chronological train/validation/test split with a one-day embargo; past-only per-card features; LightGBM early-stopped on validation PR-AUC; isotonic calibration; threshold chosen on validation by minimising an illustrative cost function; SHAP reason codes; PSI and adversarial-validation drift checks.

No results are reported. The pipeline is complete and covered by automated tests, but it has only been run on synthetic data with the IEEE-CIS schema, whose metrics are meaningless. The real run on the Kaggle IEEE-CIS data is pending, and this page will be updated with numbers from results/metrics.json only after that run.

Known design weakness found during testing: expanding-window history features drift by construction; rolling windows are the planned fix.
